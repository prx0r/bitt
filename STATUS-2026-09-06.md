# BitSec Status Report — September 6, 2026

## Executive Summary

We're trying to beat BitSec SN60 — find ALL high/critical vulnerabilities in smart contracts. The scoring is binary per project: find every single one or score 0. No partial credit.

**Current state:** 9% average DR. Best single result: coded-estate 55.6% (5/9). Target: 83.3% (15/15 projects).

**Core problem:** We find real vulnerabilities, but they're NOT the ones the benchmark expects. The benchmark expects business logic bugs (slippage, reservation theft, fee calculation). We find implementation bugs (access control, input validation).

---

## What We Learned From Research

### LogicScan (Feb 2026, 85.2% F1)
- **Key insight:** Mature on-chain protocols implicitly encode well-tested business invariants
- **Approach:** Mine invariants from 43,749 production contracts, compare against target
- **Method:** Contrastive auditing — "which invariants does the reference enforce that the target is missing?"
- **Result:** 94.3% recall on DeFiHacks, 7.1% FP rate

### Knowdit (Mar 2026, 100% high-severity)
- **Key insight:** Recurring DeFi vulnerabilities share the same economic mechanisms
- **Approach:** Knowledge graph from human audit reports + multi-agent PoC execution
- **Method:** Specification generation → PoC synthesis → PoC execution → finding reflection
- **Result:** All 21 high-severity, 90% medium-severity across 11 Code4rena projects

### What This Means For Us
We need to stop analyzing contracts in isolation. We need to compare against reference implementations and detect missing invariants.

## The 10 Mistakes We Keep Making

1. **Finding wrong vulns** — real bugs, wrong bugs
2. **Optimizing F1 instead of project pass** — 90% DR = 0 points if you miss 1
3. **Custom evaluators** — built our own scorers instead of using official sandbox
4. **Single-pass analysis** — no architecture understanding, just pattern matching
5. **Hardcoded API keys** — 3 candidates had secrets in code
6. **51% of runs never complete** — pipeline timeouts/failures
7. **"Unknown vulnerability" titles** — model can't articulate what it found
8. **Evolution without grounding** — mutating prompts when architecture is wrong
9. **Duplicate data paths** — scores in 3 places, evolution in 4 places
10. **Stale candidates cluttering** — superseded agents still in directory

for run in range(3):
    agent_output = run_agent(project)
    for expected_finding in project.high_critical_vulns:
        matched = llm_semantic_match(expected_finding, agent_output.vulnerabilities)

    execution_pass[run] = all_found  # ALL must be found

# Final score:
