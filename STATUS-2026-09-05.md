## The Problem

**The agent finds real vulnerabilities but they're the WRONG vulnerabilities.**

Our agent does generic static analysis:
- "Unchecked Return Values"
- "Missing Approval Cleared After Transfer"
- "Potential integer overflow"

Ground truth has specific design-level bugs:
- "createPoolD650E2D0 will not work due to mismatch in solidity and stylus function definitions"
- "Users are incorrectly refunded when liquidity is insufficient"
- "Inverted ERC721Receiver check makes safeTransferFrom unsafe"

The gap is NOT about detection ability. It's about **understanding project architecture deeply enough to find the specific bugs human auditors found**.

## What This Means

Getting to 80% DR requires the agent to:
1. Read and understand entire project architecture
2. Trace data flow across functions and contracts
3. Understand business logic and invariants
4. Find design-level flaws, not just pattern-matched issues

This is a fundamentally harder problem than what we've been attempting. The current approach (analyze each file independently, 3 turns per file) cannot find cross-function, cross-contract design bugs.

## The Honest Question

Is this solvable with mimo-v2.5 + the current architecture? Or does it require:
- A much larger context window (to read entire codebases)
- A more capable model (to reason about architecture)
- A fundamentally different approach (two-phase: map architecture → find bugs)

## What Works
- Agent runs reliably across all projects
- No crashes, consistent output
- Content fallback patch works
- Proxy handles load well
- Batch runner handles staggered execution

## What Doesn't Work
- Generic findings don't match specific ground truth
- Per-file analysis misses cross-file bugs
- Current model may not be capable enough for architectural reasoning
- 1% DR vs 80% target is a 80x gap
